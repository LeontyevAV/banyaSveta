# banyaSveta

Telegram-бот для бани «Света», бот: **@banya_sveta_bot** («БАНЯ СВЕТА | бот», id `7609892461`).
Проект — порт существующего Node/TS-бота (telegraf + nestjs) на Python/aiogram.
TS-референс: `~/work/web/labots/backend/bot_banya` (файлы `src/modules/bot/bot.update.ts`,
`bot.keyboards.ts`, `bot.constants.ts`, `src/common/bot.utils.ts`). Тексты кнопок уже перенесены
в `consts.py`.

## Быстрый старт (новая сессия)

1. Прочитай этот файл целиком.
2. Проверь `.env` (секреты): `BOT_TOKEN` (рабочий, @banya_sveta_bot), `SYSTEM_TOKEN`
   (бот системных сообщений, пока не используется), `PG_PASSWORD`, `PROXY_URL`, `DEBUG`,
   `DEBUG_USER_ID`.
3. Запуск бота (из корня проекта):
   ```bash
   cd ~/work/bots/banyaSveta
   venv/bin/python3 run.py          # либо: venv/bin/python3 -m bot
   ```
   Остановка — Ctrl+C. Логи: консоль + `bot.log` (RotatingFileHandler) в корне.
4. Линт/формат (ruff стоит глобально, в `venv` его нет):
   ```bash
   python3 -m ruff check . --exclude venv,tmp
   python3 -m ruff format . --exclude venv,tmp
   ```
   (либо один раз: `venv/bin/pip install ruff`, тогда `venv/bin/python3 -m ruff ...`.)
5. Тестовые скрипты — в `tmp/` (в git, но это черновики; в TODO — вынести в `.gitignore`).
   Пути внутри части скриптов хардкодят старый `/home/sasha/...` — при запуске заменить на
   `/home/leontyevav/...` (например `sed "s#/home/sasha#/home/leontyevav#g"`).
6. Git-команды выполняет **только пользователь**. Ничего не коммитить/пушить самому.

## Стек

- Python 3.10 (venv в `venv/`; WSL Ubuntu 22.04)
- aiogram 3.31 (+ `aiohttp-socks` — нужен для прокси)
- PostgreSQL + asyncpg (БД `labots`, общая для нескольких ботов)
- pydantic / pydantic-settings, PyYAML
- ruff (single quotes, запускается из системного python)

## База данных

- PostgreSQL, БД `labots`, схема `public`. **БД общая** для нескольких ботов
  (`@banya_sveta_bot`, `@banyatest_bot`, `@lalocaltest_bot`, `@lapuzzlebot`, `@todola_bot`).
  Любые запросы скоупить по `bot_id`.
- Наш бот: `bots.name = "@banya_sveta_bot"` → `bot_id = 1`; тестовый `@banyatest_bot` → `4`.
- **Миграция snake_case применена 2026-10-07** (`tmp/migrate_snake.py --apply`):
  `createdAt→created_at`, `updatedAt→updated_at`, `userTelegramId→user_telegram_id`,
  `passwordHash→password_hash`, `lastname→last_name`, `sexid→sex_id`,
  `refreshtoken→refresh_token`, `avatarid→avatar_id`, `extid→ext_id` (таблицы
  `userstelegram`, `userevents`, `users`, `_files`, `_session`, `posts`).
  Скрипт делает только `RENAME COLUMN` (обратимо).
- **Осторожно**: TS-боты (`bot_banya`, `bot_empty`, `bot_AI_test`, `api_banya`) в Sequelize
  не используют `underscored: true`, т.е. могут ждать camelCase. Переименование уже сделано —
  при проблемах у соседних ботов миграцию нужно откатывать/править их.
- Таблицы: `bots`, `userstelegram`, `userevents`, `usereventtypes`, `users`, `_files`,
  `_session`, `posts`.
- Важные детали:
  - `userstelegram`: уникальность `(user_telegram_id, bot_id)`; enum
    `user_telegram_status_enum` (`creator/administrator/member/restricted/left/kicked/bot_is_blocked`).
  - `userevents.user_telegram_id` — **FK на `userstelegram.id`** (не на telegram id!).
  - `userevents.ext_id` — в БД **без** unique-индекса (в TS-сущности декларировался), поэтому
    пустой `ext_id=''` в `log_button` не конфликтует.
  - `userevents` не имеет `bot_id` — скоуп через `userstelegram.bot_id`.
  - `usereventtypes`: 1 исходящие сообщение, 2 `/start`, 3 местоположение, 4 кнопка,
    5 входящие сообщения.
  - `_session` — telegraf-хранилище (`{"__scenes":{}}`), aiogram его не использует.
  - Броней/услуг/расписания/цен в БД **пока нет** — нужно заводить.

## Логика (текущая)

- `/start` → `BOT_CONTENT_START_TEXT` + reply-меню (`main_menu_keyboard`, «Модерация»
  только админам) → отдельный `cmd_start`.
- Reply «👩🏼🏠 О Мастере и бане» → ответ «Выберите заинтересовавший вас пункт» +
  `inline_master_banya_keyboard`, лог, удаление сообщения пользователя.
- Reply «📋 Услуги» → «Какая информация вас интересует?» + `inline_services_keyboard`.
- Reply «💌 Подарочный сертификат» → копия [64] из `channel_info` + `certificate`, удаление.
- Reply «🎁 Получить подарок» → `user_is_subscribed`:
  подписан → копия [65] + `prev`, удаление; иначе текст + `subscribe` (url `channel_url`).
- Reply «💻 Модерация» (только админы) → справка по командам, лог, удаление.
- Callback «О Мастере»/«О Бане» → копия [57,58]/[51] + `about_master`.
- Callback программы/расписание → копия [52/53/54/78/63] + `service_info`.
- Callback «Правила бронирования» → копия [46] + `prev`.
- Callback «Сертификат» → копия [64] + `certificate`.
- Callback «Отзывы» → копия [62] + `reviews`; «Оставить отзыв» → [61] + `prev`.
- Callback «Контакты» → `user_is_subscribed` определяет подпись кнопки канала
  (`Перейти`/`Подписаться`), копия [55] + `contacts`.
- Callback `prev:...` → `navigation.py`: удаляет скопированные сообщения.
- Логирование кнопок: `log_button` пишет `userevents` (тип «кнопка») + upsert юзера.
- `copy_message_from_channel` принимает и `Message`, и `CallbackQuery`; для callback в конце
  отвечает `answer('')`. Ошибки → `send_error_to_admin` (BOT_ADMIN_ID).

## Соглашения (для ассистента)

- Только single quotes (ruff). Комментарии в код не добавлять без просьбы.
- Секреты — только в `.env`. Временные файлы/данные — в `tmp/`.
- `asyncpg` для PostgreSQL. Настройки — pydantic-settings.
- Схему общей БД менять осторожно (влияет на другие боты); только через `tmp/migrate_*`.
- callback_data ≤ 64 байт (самая длинная — «Тотальная забота» ≈ 63 байта).
- Пути в `tmp/*.py` могут хардкодить `/home/sasha/...` — поправить при запуске.
- `.opencode.md` менять только с явного разрешения пользователя.
- Git-команды не выполнять (только пользователь в VS Code).
