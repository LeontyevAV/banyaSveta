# banyaSveta

Telegram-бот для бани «Света», бот: **@banya_sveta_bot** («БАНЯ СВЕТА | бот», id `7609892461`).
Проект — порт существующего Node/TS-бота (telegraf) на Python/aiogram.
Исходники TS-референса дают тексты кнопок (`consts.py`) и логику сценариев.

## Быстрый старт (новая сессия)

1. Прочитай этот файл целиком.
2. Проверь `.env` (секреты): `BOT_TOKEN` (рабочий, @banya_sveta_bot), `SYSTEM_TOKEN`
   (бот системных сообщений), `PG_PASSWORD`, `PROXY_URL`, `DEBUG`, `DEBUG_USER_ID`.
3. Запуск бота (из корня проекта):
   ```bash
   cd ~/work/bots/banyaSveta
   venv/bin/python3 run.py          # либо: venv/bin/python3 -m bot
   ```
   Остановка — Ctrl+C.
4. Линт/формат:
   ```bash
   venv/bin/python3 -m ruff check . --exclude venv,tmp
   venv/bin/python3 -m ruff format . --exclude venv,tmp
   ```
5. Тестовые скрипты — в `tmp/` (не в git): `smoke_db.py`, `menu_check.py`,
   `inline_check.py`, `prev_check.py`, `config_check.py`, `inspect_db.py`.
6. Git-команды выполняет **только пользователь**. Ничего не коммитить/пушить самому.

## Стек

- Python 3.12 (venv в `venv/`)
- aiogram 3.x (+ `aiohttp-socks` — нужен для прокси)
- PostgreSQL + asyncpg (БД `labots`, общая для нескольких ботов)
- pydantic / pydantic-settings, PyYAML
- ruff (single quotes)

## База данных

- PostgreSQL, БД `labots`, схема `public`. **БД общая** для нескольких ботов
  (`@banya_sveta_bot`, `@banyatest_bot`, `@lalocaltest_bot`, `@lapuzzlebot`, `@todola_bot`).
  Любые запросы скоупить по `bot_id`.
- Наш бот: `bots.name = "@banya_sveta_bot"` → `bot_id = 1`; тестовый `@banyatest_bot` → `4`.
- Колонки приведены к snake_case (миграция `tmp/migrate_snake.py`, выполнена 2026-10-05):
  `createdAt→created_at`, `updatedAt→updated_at`, `userTelegramId→user_telegram_id`,
  `passwordHash→password_hash`, `lastname→last_name`, `sexid→sex_id`,
  `refreshtoken→refresh_token`, `avatarid→avatar_id`, `extid→ext_id`.
- Таблицы: `bots`, `userstelegram`, `userevents`, `usereventtypes`, `users`, `_files`,
  `_session`, `posts`.
- Важные детали:
  - `userstelegram`: уникальность `(user_telegram_id, bot_id)`; enum
    `user_telegram_status_enum` (`creator/administrator/member/restricted/left/kicked/bot_is_blocked`).
  - `userevents.user_telegram_id` — **FK на `userstelegram.id`** (не на telegram id!).
  - `userevents` не имеет `bot_id` — скоуп через `userstelegram.bot_id`.
  - `usereventtypes`: 1 исходящие сообщение, 2 `/start`, 3 местоположение, 4 кнопка,
    5 входящие сообщения.
  - `_session` — telegraf-хранилище (`{"__scenes":{}}`), aiogram его не использует.
  - Броней/услуг/расписания/цен в БД **пока нет** — нужно заводить.

## Настройки

- `.env` — только секреты, приоритет над `settings.yaml`:
  `BOT_TOKEN`, `SYSTEM_TOKEN`, `PG_PASSWORD`, `PROXY_URL`, `DEBUG`, `DEBUG_USER_ID`.
- `settings.yaml` — не-секретное: `log_level`, `pg_host`, `pg_port`, `pg_database`,
  `pg_username`, `bot_name`, `channel_info`.
- Чтение — `from config import settings` (pydantic-settings + кастомный YAML-источник
  ниже по приоритету, чем env/.env).
- `channel_info: "@banya_sveta_info"` — инфо-канал для `copy_message`; бот должен быть
  в нём администратором.

## Логика (текущая)

- `/start` → текст `BOT_CONTENT_START_TEXT` + reply-меню (`main_menu_keyboard`).
- Reply «👩🏼🏠 О Мастере и бане» → `menu.py`: ответ «Выберите заинтересовавший вас пункт»
  + inline `inline_master_banya_keyboard`, лог кнопки, удаление сообщения пользователя.
- Callback «👩🏼 О Мастере» (`[57,58]`) / «🏠 О Бане» (`[51]`) → `about.py` →
  `copy_message_from_channel` (`copy` from `channel_info`), на последнее сообщение цепляется
  `keyboard_inline_about_master` (`❓ Задать вопрос` url + `<< Назад`).
- Callback `prev:...` → `navigation.py`: удаляет скопированные сообщения.
- Логирование кнопок: `log_button` пишет `userevents` (тип «кнопка») + upsert юзера.
